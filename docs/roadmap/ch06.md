Chapter 6 — Data Model & Core Logic
Spec
This chapter is the contract between the Executa ( executas/tokenbrief/), the UI bundle
( ui/) and the prompts in Chapter 9. Every type, threshold and prompt string here is
referenced by name in Chapter 10's code; change them here first, then there.
6.1 Ground rules
Numbers come from APIs, never from the model. The LLM receives a FACTS object
and may only reference values through {F#} placeholders. The UI substitutes the real
numbers after validation (§6.6).
Every metric carries its source. Sourced<T> records source and asOf so the brief
can print "price: CoinGecko, 12:03 UTC".
A run must degrade, not fail. If CoinGecko is rate-limited but DexScreener answers,
the brief is produced with null fields and a PARTIAL_DATA banner. If the LLM is
unavailable, a template brief is produced. Only NOT_FOUND and INPUT_INVALID end a run
without a brief.
Four pure tools. resolve_token, fetch_metrics, fetch_pairs, risk_flags (names are
the Executa tools[].name values in Chapter 10). risk_flags takes the outputs of the
other two as arguments, so it is deterministic and unit-testable without network.

6.3 resolve_token
Input: { query: string }. Output: ResolvedToken.
6.3.1 Parse the query
Order matters; the first matching rule wins.
# Rule (on trimmed input) kind Extracted hints
1 Matches ^https?:// url see table below
2 Matches ^0x[0-9a-fA-F]{40}$ evm_address address lower-cased
3 Matches ^[1-9A-HJ-NP-Za-km-z]{32,44}$ solana_address address as typed
4 Matches ^\$?[A-Za-z0-9.\-]{1,15}$ ticker strip leading $, upper-case
5 Anything else (spaces, > 60 chars, emoji) invalid —
Rule 3 is a base58 shape check, not a checksum; a 40-character hex string without 0x is
treated as a ticker and will fall to not_found, which is the correct answer for a malformed
address.
URL parsing (host matched after stripping www.):
Host Path pattern Hints
coingecko.com /en/coins/<id> (any locale seg‐
ment)
cgIdHint=<id>
coinmarketcap.com /currencies/<slug>/ cmcSlugHint=<slug>  (used as a search
term)

any other — kind=invalid
DexScreener URLs point at a pair address, not a token: pairHint is looked up via GET /
latest/dex/pairs/<chain>/<pairAddress>  and the baseToken.address becomes address

6.3.2 Resolve to a canonical identity
Canonical identity = CoinGecko id when the token is listed there, else chain:address from
DexScreener.
resolve(query):
  q = parse(query)
  if q.kind == "invalid": return not_found(reason="INPUT_INVALID")
  if q.cgIdHint:
    coin = cg.getCoin(q.cgIdHint)          # 404 → fall through to search
    if coin: return resolved(fromCoin(coin), source="coingecko")
  if q.kind in (evm_address, solana_address) or q.pairHint:

    addr = q.address or ds.pairBase(q.chainHint, q.pairHint)
    pairs = ds.tokenPairs(addr)            # may be empty
    coin  = cg.searchByContract(addr)      # /coins/<platform>/contract/<addr>
                                           # tried on each platform in pairs' chains
    if coin:  return resolved(fromCoin(coin) + primaryChain from pairs, "coingecko")
    if pairs: return resolved(fromPairs(pairs), source="dexscreener")
    return not_found
  # ticker (or cmc slug used as a ticker-like search term)
  term = q.cmcSlugHint or q.raw
  hits = cg.search(term).coins             # already sorted by CG relevance
  same = hits where symbol == term (case-insensitive)
  if same.length == 0: same = hits[0:5]    # fuzzy: name match
  ranked = cg.markets(ids=same.ids)        # fills market cap + rank
           sorted by marketCapUsd desc, nulls last
  if ranked.length == 0: return not_found
  if ranked.length == 1: return resolved(ranked[0], "coingecko")
  top, second = ranked[0], ranked[1]
  if top.marketCapUsd and (second.marketCapUsd is null
       or top.marketCapUsd >= 20 * second.marketCapUsd):
    r = resolved(top, "coingecko"); r.token.twinTickers = ranked[1:]; return r
  return ambiguous(candidates = ranked[0:RESOLVE_MAX_CANDIDATES])
Decision rules:
Dominance threshold 20×: PEPE resolves straight to the largest PEPE, and the others
are still reported as twinTickers so risk_flags can raise TWIN_TICKER. Below 20× the UI
shows a picker ("Which ARB?") with name, chain, market cap and rank; picking a
candidate re-runs resolve_token with query = candidate.cgId , which hits the cgIdHint-
like path ( cg.getCoin).
Contract lookups try the platform ids in this order when chainHint is absent: the chains
present in DexScreener pairs, then ethereum, binance-smart-chain, solana, base, 
arbitrum-one, polygon-pos (CoinGecko platform ids, per Chapter 5 [VERIFY]).

6.4.3 Pair selection ( fetch_pairs)
Call DexScreener token pairs for address; if chain is given, drop pairs whose chainId
differs.
Drop pairs with liquidity.usd < 1000 unless that leaves zero pairs (then keep the top
one so NO_SELLS/ FRESH_PAIR can still fire).
Deduplicate by pairAddress; sort by liquidity.usd desc; keep PAIRS_TOP_N = 5.
totalPairsSeen is the count before step 2 (used by SINGLE_PAIR).
liquidityUsd (in Metrics) is the sum over the kept pairs — an under-estimate when a
token has more than five pools, which is the conservative direction for risk.
6.4.4 Partial data
Each upstream call is independent. A failure appends "<source>:<status|timeout>"  to 
Metrics.errors, sets partial=true, and leaves the affected fields { value: null, source:
null, asOf: null }. The tool still returns success: true; only a failure of both sources for
an address-only query returns success: false, error: "UPSTREAM_DOWN" .

Rules:
A rule with any null input does not fire and instead adds evidence: { skipped:
"<field> null" } to a single PARTIAL_DATA flag; silence is never mistaken for safety
because the UI shows "not checked: liquidity" from that evidence.
Ratios use marketCapUsd only when > 0; CoinGecko reports 0 for coins without
circulating supply data, which becomes null in §6.4.2.
oldestPairAgeDays uses the minimum pairCreatedAt across all pairs seen (before the
liquidity filter), so a fresh token with one dust pool still shows as fresh.
Messages contain no digits (they pass through the same numeral validator as LLM text,
§6.6.4); numbers are rendered from evidence by the UI.
"Honeypot hints where free data allows" (brief) is exactly NO_SELLS plus 
SINGLE_PAIR+ FRESH_PAIR co-occurring; the UI labels that combination "exit-liquidity
risk", nothing stronger. No contract simulation is done.

6.6.2 System prompt (full text)
You are TokenBrief, a research assistant inside the Anna app. You write short,
neutral briefs about crypto tokens for people deciding whether to look closer.
HARD RULES
1. You never invent, estimate, round, or recall a number. The only numbers that
   may appear in your output are placeholders of the form {F1}, {F2} ... that
   refer to the FACTS object. Write the placeholder, not the value.
2. Do not write any digit character at all. The single exception is the literal
   strings "24h", "7d", "1h", "30d" when naming a time window.
3. If a fact is "n/a", say that the data is not available; do not guess it.
4. Every claim about price, size, liquidity, age, volume or socials must cite
   the placeholder it is based on, in the same sentence.
5. The risk section may only discuss flags present in FACTS (F14 and later).
   Do not add risks that are not in FACTS. Do not soften a flag with severity
   "high".
6. Nothing you write is financial advice. Do not recommend buying or selling.
   Do not use the words "moon", "gem", "guaranteed", "safe".
7. Output exactly one JSON object matching OUTPUT_SCHEMA. No markdown fences,
   no text before or after the JSON.
8. Language: write in {{LANG}}. Keep ticker symbols, chain names and
   placeholders verbatim.
STYLE
- Plain sentences. Second person is fine. No hype, no emojis.
- "what": one paragraph (max 4 sentences) that says what the token is, using
  D1 if present; if D1 is "n/a", say that no curated description exists.
- "narrative": what it is known for right now, based only on FACTS (categories,
  rank, age, 24h change). Max 3 sentences.
- "risk_commentary": walk through the flags from most to least severe, one
  sentence each, citing placeholders. If there are no flags, say that no
  automated flags fired and that this is not proof of safety.
- "questions": exactly five questions a careful person should answer before
  buying, each specific to this token's FACTS (e.g. about the FDV gap, about
  the fresh pair, about the missing socials).
- "share": a post of at most 240 characters for X/Telegram: symbol, one-line
  what, the two most important numbers as placeholders, the top risk if any.
- "confidence": "low" if 3 or more facts are "n/a" or if the token is not on

6.6.3 Output schema
The OUTPUT_SCHEMA block above is the exact JSON Schema used by ui/src/synthesis/
validate.ts (a hand-rolled checker — no ajv in the bundle; zod is acceptable if Claude
prefers it, ≤ 15 KB gzipped).
6.6.4 Validation algorithm
validate(raw, facts):
  text = raw.trim(); strip a leading ```json fence and trailing ``` if present
  obj  = JSON.parse(text)                 → fail("PARSE")
  check required keys, types, lengths, enum, additionalProperties
                                          → fail("SCHEMA:<path>")
  for each string field s (and each question):
    s2 = s.replace(/\{F\d+\}|\{D1\}/g, "").replace(/\b(24h|7d|1h|30d)\b/g, "")
    if /\p{Nd}/u.test(s2):                → fail("NUMERAL:<field>")
    for each {Fn}/{D1} in s: if not in facts → fail("UNKNOWN_FACT:<id>")
  return ok(obj)
Retry policy: on any fail, one second llm.complete call with the same system prompt plus
a user message Your previous output failed validation: <reason>. Return only the
corrected JSON. If that also fails → template fallback: text.en = null, 
llm.templateFallback = true , and the UI renders the numbers table, the flag list with rule
text, and five generic questions from ui/src/synthesis/fallback.ts . The run still counts:
the primary function (fetch + flags + brief view) completed.
6.6.5 Placeholder substitution
{Fn} → formatted value: usd → $1.23, $45.6K, $1.20M, $3.4B (3 significant figures; sub-
cent prices use up to 8 decimals with subscript-free notation 0.00001234); pct → +12.3%;
days → 412 days; count → 1,234; text → as-is. For lang = "fa", numbers are formatted
with Intl.NumberFormat("fa-IR")  and the $ sign is kept. Unknown placeholders never
reach this step (validation rejects them).
